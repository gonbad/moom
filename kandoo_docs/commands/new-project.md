# /new-project

Read the applied version and project ledger. Treat the argument as a description. When omitted ask for a short description, allowing the person to leave the idea for later. Use any already supplied project-one facts. Suggest a slug and the sibling location ../SLUG; agree on both during this step. Accept a custom path outside this Kandoo, including an existing repository root. Resolve the absolute path on the actual OS. Check for overlapping registered project roots, existing host instructions, skills and files before installing. Preserve unrelated work and remotes. If two files require integration, agree on a merge or a separate directory and restart preflight.

When there is real project context, prepare an interpretation in the current Kandoo dossier, in the project document language. Preserve provenance and distinguish assumptions from user words. Otherwise leave it empty. For a shared method update the non-secret instructions in kandoo_docs/living/server.md; reuse the configured scope, and include only the shared target's authorized credentials from ignored kandoo_docs/secrets/credentials.md. Verify protected local access/ACLs. Missing credentials stay pending. Allocate nothing in the method workspace.

The assistant invokes `python3 scaffold.py create SLUG DESTINATION` with separate, OS-quoted arguments. Add `--interpretation FILE` only for the prepared interpretation, and `--shared-access` when the authorized shared access is available. The helper verifies the applied snapshot, installs full project-only command bodies and pointers, initializes or reuses a project-root Git repository, and registers the path and revision. Inspect collisions before retry. A registered result is resumed in place. After interruption inspect both ledger and destination; recover only files verified against the sealed version. The locks in kandoo_docs/living/.scaffold.lock and the destination .scaffold.lock record a PID. After a hard interruption, verify that its process has ended and reconcile the destination against the seal before clearing that abandoned lock. Never clear a nonempty destination.

Verify the blank raw idea, interpretation, constitution, all host copies, status and git root. Localize the project server record if present. Preserve its technical identifiers. Verify the local credentials file is ignored and protected if present. The helper preserves existing .gitignore content and appends the project rules as needed. Review the resulting diff. Recommend a participant-owned project remote. Preserve a working remote, record the credential-free URL and backup state in the project ledger; local-only is valid. Verify a safe initial checkpoint when identity is available, staging only reviewed project files. Record actual checks and hand off with the absolute folder for the new AI session, its docs/ Obsidian vault, the exact blank docs/versions/0.1/00-user-idea-input.md path and /idea (or $idea). Keep Kandoo progress independent.
