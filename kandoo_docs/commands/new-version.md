# /new-version

Read the current applied version and method status. Resume an existing open change dossier; otherwise increment the minor component and create kandoo_docs/versions/VERSION/. Never increase the project product version here. Include unresolved findings in living/roadmap.md, even when their original notes already have inspection receipts. Link each disposition back to its proposal. Collect the requested changes and unread notes from registered docs/method-notes/ outboxes. Group by observed symptom, affected step and cost. Evaluate whether each finding generalizes across projects or belongs in local overrides. Record accepted, deferred and local-only dispositions and receipt hashes after persisting the evidence. Leave unavailable paths pending.

Write separate change records as applicable for mission, workflow, step procedures and template code. For a changed pipeline map added, removed, renamed, split and merged steps, prerequisites and migration implications; preserve evidence for completed work. Review proposed changes with the participant. Update affected living sources and template, then /apply. Record the applied digest and leave existing projects pinned until explicitly selected for /migrate.
