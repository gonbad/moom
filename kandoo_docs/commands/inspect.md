# /inspect

Ask for a slug if missing. Resolve its path from living/projects.md. Read the named project’s installed Kandoo version in status, relevant method notes, current status and only the evidence needed for the failed step. Identify what was expected, what happened, the cost, and whether this is a product defect, a local exception or a repeatable method defect. If a change dossier is open, record the diagnosis there. Otherwise append it to kandoo_docs/living/roadmap.md for the next /new-version. Link the staged finding from its receipt. Leave the project intact. Route a product repair to its /issue; stage reusable changes for /new-version. A single example needs a reason the change generalizes. Mark processed notes by exact slug, filename, hash and disposition in the note receipts section of living/projects.md. Inspecting an inaccessible project leaves it pending.

Inspect procedure, domain and shared-asset notes. Verify the cited artifact and promote accepted assets, facts and prompt constraints into the next Kandoo version. Keep a receipt for each note.
