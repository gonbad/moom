# /inspect

Ask for a slug if missing. Resolve its path from living/projects.md. Read the named project’s method stamp, relevant method notes, current status and only the evidence needed for the failed step. Identify what was expected, what happened, the cost, and whether this is a product defect, a local exception or a repeatable method defect. If a change dossier is open, record the diagnosis there. Otherwise append it to kandoo_docs/living/proposals.md for the next /new-version. Link the staged finding from its receipt. Leave the project intact. Route a product repair to its /issue; stage reusable changes for /new-version. A single example needs a reason the change generalizes. Mark processed notes by exact slug, filename, hash and disposition in living/note-receipts.md. Inspecting an inaccessible project leaves it pending.
