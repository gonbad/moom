# /migrate

1. Ask for one slug, a list, or explicit “all” if none was supplied. Resolve each ledger path, git root, installed stamp and target applied version. Skip already-current projects. Coordinate a quiet point with the project session. Abort that target on path/identity mismatch, an unknown stamp or interrupted prior migration until reconciled.
2. Render the target and, where needed, earlier sealed baselines into separate new temporary directories using `python3 scaffold.py render VERSION NEW_TEMP_PATH`. Compare by path and SHA256 against docs/method/stamp.md, which lists each installed method-owned file. Use the individual installed hashes for mixed-version projects. Never sweep directories. Protect the raw input, all versions, living docs, method notes, secrets, local.md, existing materials, artifacts, Git configuration and unrelated edits. Preserve a customized .gitignore. Inspect the real target for ignored and untracked files at every proposed destination, including its parents. Flag drift, conflicting additions/deletions and case-only renames for explicit resolution. Copy only reviewed paths.
3. Read current progress and the step map. Freeze completed step bodies and their deliverables. For active projects map the current step to a concrete successor, explicitly resolving ambiguity. Use the new procedure for current/future steps. Check added requirements against actual existing artifacts; record “satisfied by existing evidence”, “pending”, or “not applicable” with reasons. For steps added behind the completion boundary offer a documented skip. Preserve open questions, answers and acceptance. Plan changed reference/constitution dependencies so retained completed work remains interpretable.
4. Show a per-project diff of additions, edits, removals, preserved drift, status delta and resume command. Require explicit confirmation of the targets and diff. Recheck paths, hashes and Git status after confirmation. Use a clean, committed project checkpoint including reviewed local changes; if HEAD is unborn or the tree is dirty, arrange a reviewed local commit or defer this target. Never commit ignored secrets. Save the exact SHA and create a unique backup branch there. A branch alone cannot capture uncommitted files.
5. Apply and verify the approved diff in a temporary Git worktree based on that SHA. Update status and append a migration event. Recompute the installed stamp from actual owned bytes, retaining hashes of frozen files. Include the method version and change summary. Validate host copy equality per command, local references, current-step mapping and unchanged product evidence. Commit the verified migration. Fast-forward the project branch with `git merge --ff-only --no-overwrite-ignore MIGRATION_COMMIT` only if the original HEAD, clean status and collision checks still match. On conflict leave the original untouched and report the specific target. Remove only the temporary worktree once safe.
6. Update the ledger only for verified targets, with their resulting versions. If interrupted between fast-forward and registration, reconcile the project stamp and migration commit on retry. Keep successful results when another target is deferred. Report the checkpoint, changed version, remaining deltas and the exact current command to run in a fresh project session.
