# Structural boundaries, semantic dialogues and live effects

Keep three evidence columns: deterministic implementation checks, real configured-model
conversations and real transport/service effects. A scripted tool call or prompt-string
assertion proves wiring, not model understanding or permission integrity.

Structural cases include wrong-caller/handle type, expiry/replay, altered proposal
arguments, executor bypasses, unauthorized service resource, repeated updates, concurrent
quotas, run cancellation and delivery failure after a successful mutation. Assert both
the typed error and absence of protected state changes. Test backend eligibility inside
transactions independently of the agent's prechecks.

Configured-model dialogues should cover natural Persian/Latin names, informal agreement,
refusal, corrections, ambiguity, prompt injection from tool output, stale history and
selected outage/fallback recovery. Supply authoritative current expiry and eligibility;
verify that old history does not mint permission or restart a deadline. Use multi-turn
conversations with the actual prompt, provider and scope, not a hardcoded simulation.
When the owner defers these rehearsals, record that limit honestly and keep the procedure
available; never invent evaluation evidence.

Live wiring uses the application's actual API clients and trusted caller context.
Record revision, safe account/config identity, expected/observed result and limitations.
Check service-user restart, restored sessions, budget persistence, HTTPS and rollback.
Human product acceptance remains separate from all technical and semantic checks.
