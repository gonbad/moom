# Advanced conversational agent workflow

Resolve active Project paths and capture a real first input. Prefer the simpler bot
when deterministic behavior is sufficient. Obtain server access early, initialize
Project-owned PostgreSQL/Redis and native SSH forwarding, and retain independent
credentials, ports and deployment identity for each Project.

Extract the idea and existing assets into the initial V0.1 record. Review requirements,
service/tool inventory, SOPs/dialogues, data model and privacy before granting tool
authority. Define real integrations and every owned backend/bridge. The owner chooses
direct, soft or hard confirmation per action after seeing the tradeoffs. No global
financial/destructive-tool hard-confirmation mandate overrides that choice.

Review edge cases and actual runtime prompts. Plan every component, caller-bound tool
surface, sensitive-handle sink, budgets and fallback. Generate the implementation with
Pydantic AI/FastAPI or the reviewed equivalent and test structural controls. Wire real
model/provider and messenger accounts, verify restart/session restoration, then review
complete end-user journeys and the whole result with the owner.

Enforce per-user and global usage controls independently of model instructions. Keep
menu fallback functional when inference is unavailable or budget is exhausted. Deploy
the same dispatch code, preserve data, hand off the HTTPS endpoint from development
tunnel to VPS service and verify the actual runtime. Record machine readiness, live
integration evidence and human acceptance separately. Reuse the evolving Job across
independent Projects through the Moom adaptation/iteration flow.
