# Define acceptance journeys

Using the reviewed prototype's actual route and control names, write
LIVING/test-scenarios.md. Cover the main end-to-end journeys, authorization boundaries,
validation, empty/error states and relevant integration failures. Each scenario names
its preconditions, actions, expected visible result and persistent effects. The owner
should be able to dry-run it on the prototype. Review missing behavior and use the
approved scenarios as the implementation/acceptance contract.
