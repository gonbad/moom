# Production sequence

Resolve PROJECT, SOURCE, LIVING, VERSION, DESIGN and EVIDENCE through the Project
contract. The assistant operates commands; the person supplies product decisions,
required account login and external design choices. Preserve existing answers.

Start with the real first product and early server access. Provision isolated server
services, then record the first idea and existing-code inventory in V0.1. Review the
PRD, schema and UX before external design. Use one Claude conversation or Claude
Design to choose among three main-screen designs and produce 3–5 more key screens.
The assistant provides the prompt; the person brings approved HTML back to DESIGN.

Convert those exact designs into React, bundle Tailwind, and compare screenshots of
the source HTML and each corresponding prototype route at matched viewports/states.
Ask the owner to inspect the result. Write acceptance scenarios, then the architecture
and implementation plan before connecting the backend. Reopen only affected specs
when the prototype reveals gaps; preserve approved design choices during integration.

Test on a separate test database, walk the complete product with its owner, and deploy
with the existing target authorization. Verify deep links, assets, API errors, HTTPS,
renewal, database access and restart under the production runtime. Record readiness
and deployment evidence separately from human acceptance. Later versions use Moom's
iteration/issue flow and current Job after an adaptation check.
