# /idea

For initial intake follow the workflow constitution’s “Read the first Project input”
section and the installed `docs/kandoo/living/bootstrap.md`. If there is only template
text, invite the participant to describe their idea in their own words and wait.

Read `AGENTS.md`, all four `docs/constitution/` documents and the living profile,
Job and status under `docs/kandoo/living/`. Resolve active `ID` and `VERSION` from
status. Read the Project's living status, recorded Current input and relevant submitted
rounds. Read installed references `workflow.md`, `quality.md` under
`docs/kandoo/living/references/`. All paths are workspace-root paths.

Read the recorded Current input, existing material inventory and submitted rounds.
Reuse supplied facts before asking anything. Resolve audience, communication goal,
main claim, language, platform/aspect ratio, provisional duration and desired delivery
(HTML, silent video or voiced video). Ask only choices that affect the result; never
assume an event, character, price, style or registration window from the starter.

Maintain `docs/projects/ID/living/idea.md`, `sources.md` and `roadmap.md`. Track
source evidence, confirmed facts and delegated assumptions separately. For time-sensitive
copy record intended publication time/timezone and the relevant event/registration facts;
leave missing facts pending. Do not ask for a server or voice API credentials.
Once any specification question round is submitted, hand off to `/outline`.

Apply file-review/certainty rules and the four-domain check: Job, shared Kandoo,
active Project and write-only feedback. Preserve explicit authorization and accepted
outputs. Save evidence, current step, pending review and next action in Project
`living/status.md` and mirror shared status. Finish every reply with the full localized
Job pipeline and one exact next action, using a Markdown review/summary inside `docs/`
or the next actual command. Human acceptance is never inferred from passing checks.
