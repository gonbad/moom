# /story

Read the project constitution and current status. Use the following references from `docs/references/`: `workflow.md`, `animation.md`, `quality.md`.

Read the outline, idea and source facts. Write `docs/living/story.md`
using the animation reference's scene contract. Separate on-screen copy, narration,
subtitle policy/text and post caption; put the latter in `docs/living/caption.md`.
Record each scene's assets, actions/holds, entry/exit state, transition and timing.
Create `docs/living/assets.md` listing every visual and required state/transition, with
stable IDs. Include pronunciation and timing notes for the future voice track.

Test a rough timed storyboard/animatic and spoken read-through before locking detailed
motion. A plain local preview with placeholders is sufficient for timing exploration;
do not mistake it for an accepted visual design. Correct premature CTA, overloaded
screen text or unsupported facts now. Specification question submission resolves choices;
the authored narrative still needs explicit acceptance of its reviewed revision before
`/visuals`. Keep evidence in a numbered Markdown review in the selected dossier.
