# /visuals

Read the project constitution and current status. Use the following references from `docs/references/`: `workflow.md`, `visuals.md`, `quality.md`.

Read accepted story, asset plan and the visual reference. Take one required visual
at a time. Write its external design prompt and review instructions in the current
Markdown dossier, preserving the planned style, states and transitions. Support the
participant's available Claude Design/artifact surface or free web/desktop chatbot
returning complete HTML. Explain the `./design/` handoff and import supplied
files before asking for duplicate content.

Serve each HTML locally with the embedded SVG/CSS, state buttons and transition
controls. Inspect the actual source and appearance. Apply focused feedback until
accepted; use the documented image-generation or supplied-image fallback when needed.
Record each asset's source, hash, variants, pivot/group structure, provenance, limitations
and explicit acceptance in `docs/living/assets.md` and `docs/living/visuals.md`. Preserve original
bundles. Do not proceed to `/assets` with unreviewed required visuals or silently redraw
them while integrating. No movie rendering belongs to this step.
