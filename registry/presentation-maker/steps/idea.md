# /idea

Read the project constitution and current status. Use the following references from `docs/references/`: `slides.md`, `workflow.md`, `intake.md`.

Identify the audience's starting knowledge, setting, available time and one concrete
action they should take afterward. Extract the speaker's actual argument and sources
before proposing visuals; inspect any existing material pasted into `./existing/`
if supplied. Default to a live speaker, horizontal slides, left/right navigation and
a downloadable offline artifact; online hosting is secondary. Record orientation,
dimensions and viewing/export format, asking only about meaningful unresolved choices. Portrait and non-slide
outputs are valid. Bank out-of-scope topics in `docs/living/roadmap.md`.

Always write and maintain `docs/living/idea.md` with the talk promise,
audience, source inventory, scope, recurring worked example and measurable acceptance
criteria. Put consequential uncertain choices in
`docs/versions/VERSION/NN-questions.md` for Obsidian review; reuse answered
facts instead of interviewing again, and do not generate an entire generic deck from a
title. Once review closes, route directly to `/outline`.
