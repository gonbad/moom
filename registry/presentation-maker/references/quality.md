# Presentation verification and speaker review

| Check | Evidence | Common failure to exercise |
| --- | --- | --- |
| Source fidelity | Claim-to-source notes | Invented statistics or lost creator corrections |
| Narrative | Whole-deck walkthrough with timings | Repeated setup, missing conclusion or exercise |
| Visual readability | Desktop/mobile/print captures | Persian clipping, tiny code, cropped diagrams |
| Interaction | Keyboard, pointer and touch journey | Overlay focus loss, skipped sections counted visited |
| History/resume | Deep link, back/forward, reload | Wrong slide or stale overview state |
| Offline/export | Network-disabled opening of delivered files | CDN font, missing media, broken PDF page breaks |

Review a representative dense slide and diagram before polishing every slide. Then
walk the entire deck in order and rehearse the talk duration, including transitions.
Check sources, audience suitability and visual craft separately from browser errors.
Record technical evidence with artifact hashes; ask for the speaker's acceptance of
that same revision. Delivery packages exclude private notes unless intentionally
included. Keep unapproved changes marked as awaiting review; local delivery can be
complete without hosting, a domain or a server.
