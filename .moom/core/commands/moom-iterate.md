# Open an independent Project, Job or workspace iteration

Resolve the target from explicit context. If unclear, ask which result/entity in chat
or the harness BEFORE creating a question file. If the owner cannot locate it either,
use moom-issue's temporary intake route and diagnose first.

Read the entity's current version, roadmap and supplied input. Use iterate --target
project|job|workspace --version NUMBER --note REASON [--project ID] [--input PATH].
Use nested major/minor/patch discussions and preserve an owner-prepared 01-*.md.
Opening a Job draft does not publish it or change the installed version immediately.
Continue numbered review rounds within that iteration. Preserve prior answers.

Implement authorized scope, verify fidelity and function separately, and record
readiness versus acceptance. For a Job change, improve the actual recipe, update its
metadata.version after checks and use job-revision --note REASON. Existing Projects
use the improved Job when resumed; they do not need a forced migration or rebuild.
