# Select, adapt or resume the one production Job

Read status and the guide. If a Job already exists, resume that recipe and its first
Project; preserve learned improvements even if setup is incomplete. Do not reinstall
the starter or search the catalog for later Projects.

Otherwise capture the repeated task AND first real Project. Resolve ownership before
creating review files. Run catalog QUERY to read descriptions first, then inspect only
relevant candidates. Select/adapt one or author a new standard Skill when none fits.
Use install NAME [--source PATH] to copy a complete reusable package into job/NAME/.
Keep identity, independent metadata.version, origin and license. The active Job must
contain its required commands, procedures, scripts and assets without catalog links.

Create the real first Project with new SLUG --first. Use its actual correction loop
to refine the method. Generate host commands with sync and inspect possible collisions
with installed extensions. Aliases are job-NAME-STEP, distinct from moom- commands.
Check references and run a reviewed representative operation with verify-job --smoke
scripts/check.py (or the recipe's real equivalent). This is evidence of mechanics,
not human acceptance or native UI invocation. Check the current host's discovery when
available and report accurately if it has not been exercised.

Only after successful verification and initialization run finish-job. It removes the
starter catalog. Failed/interrupted setup retains it and resumes on the next call.
Keep docs/index.md free of obsolete discovery links. A different task family normally
starts another Kandoo, not a second Job here.
